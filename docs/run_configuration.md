# Run configuration — battery run and analysis staging
**Status: decisions ratified by the researcher 2026-08-05, except where marked OPEN. Plain-language record; register entries derive from this.**

## The run itself
One pod session, one deterministic pass. Both administration formats run in the same session against the identical frozen battery: the open-ended format is the primary study; the short answer-only format is the robustness arm, and it also serves as the pre-stated fallback reading for any open-ended choice response that resolves ambiguously (its next-token probabilities disambiguate, capping the hand-labeling burden).

Every generated response gets up to 128 tokens. If a response is cut off in a way that blocks labeling it, the automatic labeler flags it and that item is regenerated with a longer budget in the same session, before the pod closes.

Generation is greedy (deterministic) everywhere. Sampling is used only in one bounded audit: any refusal-family item where the automatic label disagrees with the designed resolution, or where the labeler is uncertain, gets five sampled regenerations in a follow-up shard the same session — used only to characterize how stable that label is, never to replace the greedy label in the analysis.

Mechanics: seed-fixed shuffled item order with tension types interleaved; every choice item administered in both option orders; internal activations captured at the pre-response anchor at every layer (half precision) along with the next-token entropy; every row carries the prompt checksum and full condition metadata; incremental atomic writes; the verification script runs before the pod is torn down. Before the real run, a 10–15 item smoke shard goes end to end — capture, manifest, verification, and an automatic-labeler pass — so the plumbing is boring by run day.

**GPU selection (ruled 2026-08-05):** in order of preference — an A100 or H100 in any datacenter (mature architecture, fully supported by the pinned environment; accept the one-time model-cache re-download and repo clone if it means leaving the storage volume's datacenter), else the RTX 4090 in the volume's datacenter (previous-generation architecture, runs the existing environment untouched, at roughly half speed — same-day results still comfortable). Blackwell-generation cards (RTX 5090, RTX PRO 6000) are excluded unless Claude Code verifies beforehand that a torch build exists satisfying both the Blackwell architecture requirement and the TransformerLens dependency pin, proven by a load test — the researcher has already established these constraints were irreconcilable once on her local machine, and stable PyTorch still ships without Blackwell kernels. Session parallelism: the comparator control + recapture and the smoke shard + battery are independent workloads and may run on two pods simultaneously (each writing to its own output directory, manifests merged and verified afterward); a single pod running them sequentially is the simpler fallback and still delivers same-day results.

## How the layer for measuring conflict is chosen (ratified)
The conflict direction is fitted, at each layer, from the designed contrast between opposition and agreement cells (same scenario, same resolution direction), using the same difference-of-averages estimator used for the refusal and emotion directions. The winning layer is the one where a direction fitted on part of the choice-family scenarios best separates opposition from agreement on choice-family scenarios it never saw (scenario-level cross-validation, stratified by tension type; ties broken by stability across neighboring layers). Reliability may disqualify a layer as unstable but never picks the winner. The refusal-family scenarios are never used in selection, so the later transfer test stays honest. Predicting the model's behavior is excluded as a selection criterion, because the claim under test is that the internal state exists whether or not it drives the outcome. If the winning layer is not layer 12, the conflict-versus-refusal comparison runs at the winning layer with a natively fitted refusal direction there, and is repeated at layer 12 (where the refusal direction carries its causal validation) as a sensitivity check.

## Analysis staging: results do not wait for hand labels
The five label-free analyses run on the designed conditions and are computable the day of the run: does a stable conflict signal exist; which layer; is it geometrically distinct from refusal; can it be reconstructed from emotion signals plus generic decision difficulty; does the choice-family-fitted direction transfer to the refusal family. Items that failed to resolve as designed only dilute these contrasts, so positive results survive later behavioral verification a fortiori. Same-day presentation carries one attached sentence: behavioral verification pending.

The automatic labeler runs in the pod session; its labels are deterministic and digest-locked at run time (Stage 1 measured it at 1.94% audited disagreement). A provisional manipulation-check table and a provisional conflicted-compliance read exist same-day, clearly marked provisional.

The researcher's audited labels arrive on her own schedule and gate only the verified tier: the manipulation-check table as evidence, the verified-subset repeat of the five analyses, and the conflicted-compliance analysis proper.

## Audit protocol (pre-stated to foreclose label-tuning concerns)
The researcher audits per-cell blind: generations are read from a text export with no analysis results attached. The automatic labels are already committed, so every correction is a documented delta against a frozen baseline. Audit scope defaults to the Stage-1 convention — a 20% stratified sample plus all uncertain rows — with eyes-on reading of every conflicted-compliance cell; the fraction may be adjusted with a documented rationale. Labels lock with a digest before the verified analyses unblind; any later change is a documented amendment, never a silent edit.

## Specified follow-ups (filed before this study's data exists)
1. **Causal follow-up — steering.** Remove the conflict direction in opposition cells (disclaimers and hedging should thin while choices hold) and inject it in agreement cells (hedging should appear unprompted), with matched-norm random directions as the specificity control and fluency checks throughout. The disclaimer/hedging behaviors established by this study's labels are the planned outcome measures. Inherits the frozen battery, capture pipeline, and labeling machinery; weeks-scale.
2. **Operationalization-diversity battery** for the formula-lock limitation (e.g., discovered-knowledge privacy), run second, once the construct has causal standing.
